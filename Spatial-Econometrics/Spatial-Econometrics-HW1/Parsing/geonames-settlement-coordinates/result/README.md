# Settlement Coordinates And Geographic Features

Файл `settlement_coordinates.csv` содержит географический слой для всех `new_id` из
`Source/Qualifying/train.csv`.

Файл `settlement_geographic_features.csv` содержит тот же географический слой без `new_id`
и без магазинных признаков. Он предназначен для переиспользования на новых датасетах через
ключи `normalized_region` и `normalized_settlement`.

Внутри есть:

- координаты центра населённого пункта;
- опорная точка Москвы;
- опорная точка региона;
- производные географические признаки для модели;
- ссылка на Yandex Maps для ручной проверки.

## How `FEATURE_RANK` Works

`FEATURE_RANK` — это словарь приоритетов типов GeoNames-объектов.

Он нужен в тех случаях, когда по одной строке из train находится несколько кандидатов в GeoNames.
Тогда кандидаты ранжируются не только по похожести названия, но и по типу объекта.

Общее правило простое:

- чем меньше значение в `FEATURE_RANK`, тем выше приоритет;
- административный центр предпочтительнее обычного населённого пункта;
- обычный населённый пункт предпочтительнее менее надёжных или служебных записей.

Примеры кодов:

- `PPLC` — столица страны;
- `PPLA` — административный центр региона;
- `PPLA2` — административный центр следующего уровня;
- `PPL` — обычный населённый пункт.

Конкретный пример:

Допустим, для строки:

- `Регион = Краснодарский край`
- `Населенный пункт = Краснодар`

после поиска осталось два кандидата:

1. `Краснодар`, `feature_code = PPLA`, `feature_rank = 1`
2. `Краснодар`, `feature_code = PPL`, `feature_rank = 5`

В этом случае будет выбран первый кандидат, потому что `1 < 5`.
То есть административный центр региона считается более репрезентативной точкой, чем просто запись
обычного населённого пункта с тем же названием.

Если же у двух кандидатов одинаковый тип, например оба `PPL`, то дальше используются дополнительные
сигналы, в первую очередь население и служебные эвристики матчинга.

Этот механизм используется в двух местах:

1. при выборе лучшей GeoNames-записи для населённого пункта;
2. при выборе `region_center` как опорного центра региона.

## Reference Points

Для расчёта фичей используются три типа точек:

| Reference point | Meaning |
|---|---|
| `settlement` | центр населённого пункта магазина |
| `moscow` | центр г. Москва |
| `region_center` | репрезентативный населённый пункт региона |

`region_center` — это не геометрический центроид региона.
Это лучший населённый пункт внутри `admin1`, выбранный сначала по `FEATURE_RANK`, а затем по
населению.

## Service Columns

В `result` есть служебные колонки, которые нужны для проверки результата и расчёта производных
географических признаков, но сами по себе не считаются модельными фичами.

| Column | Meaning |
|---|---|
| `settlement_lat` | широта населённого пункта |
| `settlement_lon` | долгота населённого пункта |
| `region_center_name` | название опорного центра региона |
| `region_center_lat` | широта опорного центра региона |
| `region_center_lon` | долгота опорного центра региона |
| `moscow_name` | название опорной точки Москвы |
| `moscow_lat` | широта Москвы |
| `moscow_lon` | долгота Москвы |
| `yandex_maps_url` | ссылка на карту для ручной проверки |

При merge в train через `Utils/preprocessing/geographic_features.py` эти служебные колонки не
подмешиваются как признаки модели.

## Model Features

Ниже перечислены именно те географические признаки, которые предполагается использовать в модели.

| Feature | What it measures | Why it may help the model | Practical note |
|---|---|---|---|
| `distance_to_moscow_m` | расстояние от населённого пункта до Москвы по Хаверсину | может отражать удалённость от крупнейшего федерального центра спроса, логистики и деловой активности | одна из самых базовых и интерпретируемых геофичей |
| `bearing_to_moscow_deg` | направление до Москвы в градусах `0..360` | помогает различать точки с одинаковой дистанцией, но разным макрорегиональным положением | raw-угол удобен для деревьев, но имеет разрыв между `0` и `360` |
| `bearing_to_moscow_sin` | синус азимута до Москвы | даёт непрерывное представление направления без разрыва на границе круга | обычно полезен вместе с `bearing_to_moscow_cos` |
| `bearing_to_moscow_cos` | косинус азимута до Москвы | дополняет `sin` и восстанавливает полный циклический сигнал направления | обычно полезен вместе с `bearing_to_moscow_sin` |
| `distance_to_region_center_m` | расстояние до опорного центра своего региона | может отражать локальную периферийность и удалённость от административного или делового ядра региона | особенно полезно для различения магазинов внутри одного региона |
| `bearing_to_region_center_deg` | направление до центра региона в градусах `0..360` | позволяет модели учитывать, в какой части региона расположен населённый пункт | как и любой raw-угол, частично дублируется `sin/cos`-кодировкой |
| `bearing_to_region_center_sin` | синус азимута до центра региона | делает локальное направление непрерывным для модели | обычно рассматривается в паре с `bearing_to_region_center_cos` |
| `bearing_to_region_center_cos` | косинус азимута до центра региона | закрывает вторую ось циклического направления до центра региона | парная фича к `bearing_to_region_center_sin` |
| `lat_delta_to_moscow_deg` | разница по широте между точкой и Москвой | даёт модели явный северо-южный сдвиг относительно Москвы | обычно интерпретируется проще, чем сырая широта |
| `lon_delta_to_moscow_deg` | разница по долготе между точкой и Москвой | помогает кодировать западно-восточное положение относительно Москвы | обычно интерпретируется проще, чем сырая долгота |
| `lat_delta_to_region_center_deg` | разница по широте между точкой и центром региона | показывает, насколько населённый пункт севернее или южнее регионального центра | локальный аналог сдвига относительно Москвы |
| `lon_delta_to_region_center_deg` | разница по долготе между точкой и центром региона | показывает, насколько населённый пункт западнее или восточнее регионального центра | локальный аналог сдвига относительно Москвы |
| `distance_to_moscow_minus_region_center_m` | разница между расстоянием до Москвы и расстоянием до центра региона | показывает соотношение глобальной удалённости и локальной центральности | удобна как interaction-like фича без ручного кросса |
| `distance_to_moscow_to_region_center_ratio` | отношение расстояния до Москвы к расстоянию до центра региона | нормализует федеральную удалённость через локальный масштаб региона | полезно там, где важнее относительное, а не абсолютное положение |

## Denis Selected Location Features

В `settlement_geographic_features.csv` отдельно зафиксирован компактный geo-slice Дениса:

- `distance_to_moscow_m`
- `distance_to_region_center_m`
- `distance_to_moscow_to_region_center_ratio`
- `distance_to_moscow_bin_q10`

`distance_to_moscow_bin_q10` хранится как сырая категориальная строковая фича и должна
передаваться в CatBoost через `cat_features`, без target encoding и one-hot encoding.

## Additional Ideas

Ниже перечислены идеи, которые сейчас не включены в основной модельный slice, но могут быть
полезны в следующих итерациях.

| Idea | Why it may help |
|---|---|
| `is_moscow` | отдельный special-case флаг для магазинов Москвы |
| `is_region_center_settlement` | флаг, что магазин расположен прямо в региональном центре |
| кластеризация координат | позволяет перейти от непрерывной географии к устойчивым гео-кластерам |
| биннинг расстояния до Москвы | может быть полезен, если модель лучше работает на дискретных гео-зонах |
| взаимодействия с населением и трафиком | помогает проверить, усиливают ли гео-фичи уже существующие соц-экономические признаки |
