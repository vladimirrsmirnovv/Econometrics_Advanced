# Приватное воспроизведение XGBoost на Kaggle GPU

Запуск использует исходные данные и функции предоставленного ноутбука. Обучаются только XGBoost: февральская валидация с исходной ранней остановкой и финальная модель с 3750 деревьями для марта 2025. CatBoost и LightGBM здесь не переобучаются. После установки зависимостей расчёт запускается в свежем Python-процессе, чтобы избежать смешения уже загруженных библиотек с установленными версиями.

`prepare_gpu.py` создаёт входной пакет в игнорируемом `upload/` и ноутбук в `kernel/`. Во входном пакете находятся исходный CSV, неизменённый ноутбук, контрольные суммы файлов и выбранных валидационных матриц. На Kaggle генератор запускается заново; признаки и преобразованная цель должны совпасть с локально воспроизведённой базой до обучения. Токен не входит в пакет и не сохраняется в файлах.

Признаки сравниваются побайтно. Для цели дополнительно сравниваются конечные значения float32 и маска исключаемых строк: [XGBoost хранит метки в Tensor<float>](https://github.com/dmlc/xgboost/blob/master/include/xgboost/data.h). Исходные цели float64 выгружаются отдельно; `compare_gpu.py` проверяет их различие с абсолютным допуском 10⁻¹² и точное равенство float32. Такой контроль учитывает машинные различия логарифмов между Windows и Linux, сохраняя проверку данных, реально поступающих в модель.

Метаданные явно задают приватность датасета и ноутбука, GPU T4 и доступ к интернету для установки зависимостей. Исходная версия контейнера Kaggle 31401 известна из метаданных ноутбука; её наличие в манифесте не означает, что сервер запустил именно этот образ. pandas 2.2.3, numpy 2.3.5, pyarrow 26.0.0 и holidays 0.106 зафиксированы для сравнения с локальным запуском. Версия XGBoost выбирается параметром `--xgboost-version` из 3.1.3, 3.2.0 и 3.4.1; по умолчанию 3.1.3, которая воспроизвела все сохранённые метрики. Фактические версии, GPU и метрики записываются в `runtime.json` и `gpu_metrics.json`.

Исходный ноутбук устанавливал XGBoost без указания версии и без обновления уже установленного пакета. Он сохранил Python 3.12.13 и номер образа, но не версию XGBoost. По [истории образов Kaggle](https://github.com/Kaggle/docker-python/releases?page=2) для проверки были выбраны кандидаты 3.1.3 и 3.2.0. С 3.1.3 получено точное совпадение MAPE, MAE, RMSE, смещения и лучшей итерации; проверка 3.2.0 не потребовалась. Это подтверждает подходящее окружение для воспроизведения, хотя исходная версия пакета не записана в экспорте. Подробности результатов находятся в `reproduction_report.md`, сведения об исходном окружении — в `source_environment.json`.

Из корня репозитория:

```powershell
& Forecasting/.venv/Scripts/python.exe -m pip install kaggle==2.2.4
$env:PYTHONUTF8='1'
& Forecasting/.venv/Scripts/python.exe Forecasting/kaggle/client_session.py
```

Токен вводится через скрытый ввод или передаётся уже установленной переменной `KAGGLE_API_TOKEN`; сохранённого токена эти файлы не содержат. После авторизации выполнить в другом терминале:

```powershell
& Forecasting/.venv/Scripts/python.exe Forecasting/kaggle/prepare_gpu.py --xgboost-version 3.1.3
```

Клиент принимает JSON-команды по одной строке:

```json
{"action":"create_dataset"}
{"action":"dataset_status","ref":"vladimirsmirnovve/x5-xgboost-reproduction-20261009"}
{"action":"push"}
{"action":"status","ref":"vladimirsmirnovve/x5-xgboost-gpu-reproduction-20261009"}
{"action":"output","ref":"vladimirsmirnovve/x5-xgboost-gpu-reproduction-20261009"}
{"action":"quit"}
```

Сначала дождаться готовности датасета, затем отправлять ноутбук. Команда `push` создаёт новую версию и запускает обучение, поэтому её не следует повторять ради проверки статуса. Полученные файлы сохраняются в игнорируемом `output/`; важные метрики и проверки сравнения выносятся отдельно. Этот запуск не отправляет submission в соревнование.

После успешного завершения и скачивания результатов запустить `compare_gpu.py`. Он проверяет признаки, цели и идентификаторы магазинов, сохраняет GPU-прогнозы и пересчитывает февральский ансамбль по исходным правилам. Замена только CatBoost на ранее проверенный вариант с пространственной историей оценивается отдельно. Финальный мартовский CSV здесь относится только к XGBoost. Каждый успешный расчёт дополнительно архивируется в `results/<версия XGBoost>/`; файлы непосредственно в `results/` и CUDA-прогнозы в общей февральской папке относятся к последнему обработанному запуску.
